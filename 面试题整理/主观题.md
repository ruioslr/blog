## 前端的角度做性能优化

从前端的角度，性能优化是一个系统工程，主要围绕 ​​加载性能、渲染性能、代码效率、网络传输、用户体验​​ 等多个方面展开。

​​1. 加载性能方面：​​ 我会尽量减少 HTTP 请求，压缩资源（JS/CSS/图片），使用 CDN 加速，按需加载（如路由懒加载、图片懒加载）、代码分割、Tree-Shaking，以及利用预加载和异步脚本等方式，让页面更快加载并尽早达到可交互状态。

​​2. 渲染性能方面：​​ 我会避免频繁的 DOM 操作与样式更新，减少重排与重绘，使用 CSS3 transform 和 opacity 做动画，利用 requestAnimationFrame 优化动画性能，对于长列表使用虚拟列表技术，避免主线程长时间阻塞。

​​3. 代码与资源优化：​​ 我会对代码进行压缩混淆、Tree-Shaking、移除未使用的代码和依赖，合理使用 Web Workers 处理复杂计算，避免内存泄漏等问题。

​​4. 网络优化：​​ 我会启用 HTTP/2 或 HTTP/3，合理设置缓存策略，减少 Cookie 体积，使用现代图片格式如 WebP / AVIF，以及 DNS 预解析、资源预加载等手段提升网络效率。

​​5. 用户体验优化：​​ 我会特别关注首屏渲染时间（FCP/LCP）、交互延迟（FID）和页面稳定性（CLS），通过骨架屏、预加载、SSR/SSG 等方式提升用户感知速度与满意度。

​​在实践中，我会结合 Chrome DevTools、Lighthouse、WebPageTest 等工具做性能分析，找出瓶颈，有针对性地优化，并持续监控线上性能表现。​


- 在提高开发效率上：
  - 开启hmr，这样就不需要手动筛选浏览器
  - 像我之前game-server使用ts-node去执行ts代码，每次启动需要几十秒的时候，换成swc之后只需要2-3秒，极大提高开发效率。
- 构建上：
  - 使用雪碧图
  - 代码分割，懒加载
  - js，css压缩
  - treeshaking
- 网络上
  - 使用http缓存，减少网络请求
  - 使用cdn减少网络延迟
  - 使用http2使得http请求可以并行
- 代码层面：
  - 尽量避免直接操作dom，减少浏览器回流
  - 对一些按钮添加防抖节流，减少同一时间多次http请求
  - 对于大量的计算可以使用webworker
  - 事件监听需要解绑
